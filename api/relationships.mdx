Examples describe fictional Brightwater Health Partners data. Replace `DEMO-` placeholders with returned IDs before sending requests. Numeric IDs are illustrative. UUID fields require valid returned UUIDs.

Use the relationships endpoints to read the agencies and agents your agency works with, and to add uplines, invite downlines and partners, or connect agents from another system.

All examples use `{BASE_URL}`, which already ends in `/v1`. Copy it from the **API Keys** screen. See [Authentication](/api/authentication) for headers.

## Endpoints

| Method | Path | Scope |
| ------ | ---- | ----- |
| `GET` | `/relationships` | `relationships:list` |
| `GET` | `/relationships/{id}` | `relationships:view` |
| `POST` | `/relationships` | `relationships:create` |

A relationship id that isn't one of your agency's returns `404`.

<ParamField query="page" type="integer" default="1">
Page number, starting at 1. Applies to list requests.
</ParamField>

<ParamField query="per_page" type="integer" default="25">
Rows per page, from 1 to 100. Applies to list requests.
</ParamField>

## List relationships

`GET /relationships` returns your agency's relationships, newest first. The list is paginated with `page` and `per_page`. See [Pagination, filtering and sorting](/api/pagination-filtering-and-sorting).

<ParamField query="type" type="string">
`upline`, `downline`, `agent` or `partnership`.
</ParamField>

<ParamField query="status" type="string">
`active`, `pending`, `accepted` or `declined`.
</ParamField>

<ParamField query="search" type="string">
Matches the other agency's name or email.
</ParamField>

<RequestExample>

```bash
curl "{BASE_URL}/relationships?type=downline&status=accepted" \
  -H "Authorization: Bearer pd_your_api_key" \
  -H "Accept: application/json"
```

</RequestExample>

## Get a relationship

`GET /relationships/{id}` returns one relationship with the products and carriers it covers.

### Carriers

Each item in `carriers` takes:

<ParamField body="product_id" type="string" required>
One of your products from [`GET /products`](/api/products).
</ParamField>

<ParamField body="carrier_id" type="string" required>
A carrier id from `GET /products`.
</ParamField>

<ParamField body="upline_id" type="string">
The id of the upline you get this carrier through, from `GET /relationships?type=upline`. Not used for uplines.
</ParamField>

For downlines, partners and agents, you can only share carriers you get through one of your active uplines. Leave out `upline_id` when only one upline offers that carrier for the product. These errors return `422`:

| Message | What to do |
| ------- | ---------- |
| `You do not have this carrier through any upline for this product.` | Add the carrier to one of your uplines first. |
| `More than one upline offers this carrier. Send upline_id to pick one.` | Add `upline_id`. |
| `This carrier is not available through that upline for this product.` | Use a different `upline_id`. |
| `This carrier is listed twice for the same product.` | Remove the duplicate. |

### Other validation errors

| Message | Cause |
| ------- | ----- |
| `An agency with this name already exists.` | A new agency's `name` is taken. |
| `Users can only be added to an agency that does not exist yet.` | You sent `users` for an existing agency. |
| `A relationship with this agent already exists.` | You're already connected to that agent. |
| `You cannot create a relationship with your own agency.` | The email belongs to someone in your agency. |
