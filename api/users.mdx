Examples describe fictional Brightwater Health Partners data. Replace `DEMO-` placeholders with returned IDs before sending requests. Numeric IDs are illustrative. UUID fields require valid returned UUIDs.

Use `GET /users` to read the users in your agency. You need a user id to set the owner of a contact or the writing agent of a policy.

All examples use `{BASE_URL}`, which already ends in `/v1`. Copy it from the **API Keys** screen. See [Authentication](/api/authentication) for headers.

## Endpoint

| Method | Path | Scope |
| ------ | ---- | ----- |
| `GET` | `/users` | `users:list` |

The response lists users whose main agency is yours, sorted by first name and then last name. It's paginated with `page` and `per_page`. See [Pagination, filtering and sorting](/api/pagination-filtering-and-sorting).

<ParamField query="search" type="string">
Matches first name, last name, full name or email.
</ParamField>

<ParamField query="status" type="string">
Only users with this status: `active`, `inactive`, `pending` or `suspended`. Any other value returns no users.
</ParamField>

## Use user ids

| Endpoint | Field | Notes |
| -------- | ----- | ----- |
| [`POST /contacts`, `PUT /contacts/{id}`](/api/contacts) | `assigned_to` | The contact's owner. On create, it defaults to the user who created the API key. |
| [`POST /policies`](/api/policies) | `assigned_to` | The writing agent. Required. |
| [`PUT /policies/{id}`](/api/policies) | `assigned_to` | Changes the writing agent. |
| [`GET /contacts`, `GET /policies`](/api/pagination-filtering-and-sorting) | `assigned_to` filter | Only records assigned to this user. |

A user who doesn't belong to your agency returns `422` with `The assigned user does not belong to your agency.`

You can't invite or edit users through the API. Admins do that in the app. See [Users and roles](/settings/users-and-roles).
